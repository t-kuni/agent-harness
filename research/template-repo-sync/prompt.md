# リサーチ課題：テンプレートリポジトリの更新を派生先リポジトリへ取り込む方法

## 背景

あるGitリポジトリ（以下「テンプレートリポジトリ」）がある。
利用者はこのリポジトリを `git clone` し、`.git` を削除して独自のGitリポジトリとして使い始める（以下「派生先リポジトリ」）。

この派生先リポジトリは独自のコミット履歴を持ち、テンプレートリポジトリとは無関係な状態になる。

その後、テンプレートリポジトリに修正・更新が入った場合、その変更を派生先リポジトリに取り込みたい。

## 問い

テンプレートリポジトリの変更を派生先リポジトリへ取り込む方法として、どのような手段があるか。各手段の具体的な手順・メリット・デメリットを明らかにしたい。

## 調査対象の手段

以下の手段について調査してほしい：

1. **git format-patch / git am を使ったパッチ適用アプローチ**
   - 特定のコミット範囲からパッチを生成し、派生先リポジトリに適用する方法
   - コンフリクト時の対処法

2. **upstream remote を追加して merge/rebase するアプローチ**
   - テンプレートリポジトリをリモートとして追加し、差分をマージまたはリベースする方法
   - `.git` を削除した後でもこの方法は使えるか

3. **git subtree を使ったアプローチ**
   - テンプレートリポジトリをsubtreeとして組み込む方法
   - 後からsubtreeとして後付けできるか

4. **git submodule を使ったアプローチ**
   - テンプレートリポジトリをsubmoduleとして組み込む方法
   - 後からsubmoduleとして後付けできるか

5. **コミットハッシュを記録してパッチ差分を生成・適用するアプローチ**
   - クローン時のコミットハッシュをファイルに記録しておく
   - 後からそのハッシュ～最新コミット間の差分を生成して適用する
   - スクリプト化した場合の具体的な実装イメージ

## 出力要件

- 出力言語：日本語
- 各アプローチについて以下を整理してほしい：
  - 具体的な手順（コマンド例を含む）
  - メリット
  - デメリット・注意点
  - スクリプト化のしやすさ（1〜5点で評価）
  - コンフリクト発生時の対処方法
- 最後に、「.gitを削除して独立させた派生先リポジトリにテンプレートの更新を取り込む」というユースケースに最も適したアプローチの推薦とその理由をまとめてほしい
