# このリポジトリについて

これは Claude Code（Anthropic製CLIエージェント）向けの「ハーネス」を管理するリポジトリである。ハーネスとは、AIエージェントが参照する知識ファイル群の総称で、`.claude/skills/<スキル名>/SKILL.md` の形式でスキルが定義される。このリポジトリには汎用的なWebリサーチを行う `research` スキルがある。

過去に行った別のリサーチにより、OpenAIのDeep Research用モデルであった `o3-deep-research` `o4-mini-deep-research` は2026年7月23日にシャットダウンされ、OpenAI公式Deprecationsページ上での推奨移行先として `gpt-5.6-sol` というモデルが案内されていることが判明した（ただし、モデル個別ページ・Deep Researchガイドページでは旧モデルが依然として現行として案内されており、情報源間で矛盾がある状態）。`gpt-5.6-sol` のモデルページには対応ツールとして `web_search`、`file_search`、`code_interpreter`、`mcp` 等が列挙されているが、`deep_research` という専用ツール名の記載はなかった。

この `research` スキルを、単発のプロンプト送信では終わらない「エージェント的な自律調査」（複数ターンにわたりツール呼び出し・推論を繰り返し、最終的に1つの調査結果を返す挙動）に対応させたいと考えている。

# 問い

OpenAIのAPIにおいて、`gpt-5.6-sol` というモデルを、単発のcompletion／レスポンス生成ではなく、「エージェント的なループ」（モデル自身が複数ターンにわたり `web_search` 等のツールを自律的に繰り返し呼び出し、最終的な回答に到達するまで自動的に継続する実行方式）で起動できるか。以下を明らかにせよ。

1. OpenAIの公式ドキュメント（platform.openai.com、developers.openai.com、openai.com/index の公式ブログ・公式Changelog）において、`gpt-5.6-sol` を用いてマルチターン・自律的なツール呼び出しループを実行する方法が説明されているか。説明されている場合、それはResponses API単体の機能（例：`background: true` と `tools` の組み合わせによる自動継続、あるいはOpenAIが定義する「エージェントループ」の仕組み）なのか、それとも別途Agents SDK（`openai-agents` 等）の導入が必要なのかを明確にする。
2. エージェント的なループを実現するための具体的なAPI呼び出し方法（エンドポイントURL、HTTPメソッド、主要なリクエストパラメータ、ツール定義の書式）を、公式ドキュメントに掲載されているサンプルコード（cURLまたはPython/TypeScript SDK）とともに示す。
3. このループ実行方式において、「1回のAPI呼び出しでモデルが複数回ツールを呼び出し続け、最終回答に到達するまで自動的に継続する」という挙動が実際に成立するのか、それとも呼び出し側（クライアント）がツール呼び出し結果をモデルに都度渡し返す「手動のツール呼び出しループ」をコード側で書く必要があるのかを明確にする。
4. `gpt-5.6-sol` がDeep Research用途（前述の `o3-deep-research` の後継としての多段階自律調査）に使われることを想定した専用の設定・パラメータ（例：`reasoning.effort`、`max_tool_calls` の推奨値）が公式ドキュメントに記載されているか確認する。
5. 公式情報で確認できない項目があれば、その旨と、確認のために参照したURL・検索クエリの結果概要を明記する。

# 出力要件

- 日本語で記述すること。
- 公式ドキュメント・公式ブログ・公式Changelogを最優先で参照し、URLを明記すること。二次情報サイトを使う場合はその旨を明記し、公式情報と区別すること。
- 「できる」「できない」を推測ではなく、実際に参照できたソースに基づいて明言すること。断定できない場合は「確認できなかった」と明記すること。
- サンプルのAPIリクエスト（curl等の疑似コード可）が公式ドキュメントに存在する場合は、そのまま引用すること。
- 参照した公式ドキュメント・情報源のURLをすべて出力の末尾に列挙すること。
- 選択肢の提示や好み・推奨の表明は不要。事実の確認結果のみを記述すること。
