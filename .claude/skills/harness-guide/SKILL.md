# 特殊ハーネスについて

## ルート直下の `CLAUDE.md` と `.claude/CLAUDE.md`

* リポジトリの主目的に基づいて常に参照するべき知識であれば配置する
* あらゆる作業に有効なドメイン知識を配置する
* 参照タイミングを限定できる知識は配置しない（`.claude/skills/` に切り出す）
  * 背景：CLAUDE.mdの肥大化を避けるため
* `xxx/CLAUDE.md` などサブディレクトリ配下のCLAUDE.mdはこのルールの対象外

## `.claude/skills/`

* 必要に応じて参照させたい知識を配置する
* frontmatter の description を索引とし、AIエージェントが自動的に知識を参照する
  * descriptionには知識のwhat(何か？), when(いつ参照するか？)を記述する


# ハーネスに知識を追加・変更する手順

1. ハーネスに「追加したい知識」を明確にする
2. SSoTチェック
  * 「追加したい知識」がすでにハーネスに記述されていないか確認する
  * 複数キーワードを grep するなどして探す
3. 配置先チェック
  * 「追加したい知識」が書かれているべきハーネスを検討する
  * ハーネスの種類・役割を考慮する（ハーネスの種類は `CLAUDE.md` を参照）
  * その知識を「どのタイミングで知っておく必要があるか」に基づいて判断する
  * メタハーネスは必ず特殊ハーネスとする
    * メタハーネス × 自然ハーネスの組み合わせは禁止
  * 自然ハーネスを追加する場合、適切な特殊ハーネスからリンク（導線）を用意する必要がある
    * 適切な特殊ハーネスが存在しない場合は、特殊ハーネスも同時に作成する
4. 判定
  * SSoTチェックNG ✕ 配置先チェックNG
    * すでに知識が存在するが、適切な箇所に記載されていない
    * 対処方法：知識の記述箇所を移動する or 最適な箇所にリンクを追加する
  * SSoTチェックNG ✕ 配置先チェックOK
    * すでに知識が存在し、適切な箇所に記載されている
    * 対処方法：なにもしなくていい or 別の対処方法が必要（「追加したい知識」で問題が解決しない可能性を疑う）
  * SSoTチェックOK
    * 対処方法： 適切なハーネスに追記or新規作成
5. ハーネスを追加・変更する

# ドメインハーネスを新規作成・更新する手順

原則:
- フォルダ構造・ファイルフォーマット・配置先は固定しない。タスクの性質に合わせて都度設計する。
- 既存のドメインハーネスへ統合できるなら新設しない。

手順:
1. オーナー要求からドメイン名、完了条件、制約、入力、出力を抽出する。
2. 既存のドメインハーネス候補を調べ、流用できるものがあれば再利用する（上記「ハーネスに知識を追加・変更する手順」のSSoTチェック・配置先チェックに従う）。
3. 足りなければ、タスクに最適な場所・構造でドメインハーネスを新設する。
   - 知識の種類（仕様、手順、検証、参照先など）に応じてファイルを分割するか統合するかを判断する。
   - 機械可読な SSoT（仕様書、スキーマ、サンプル出力など）は適切な場所へ置く。
4. 完了条件ごとの確認方法・実行入口・期待結果・手動確認点を記載する。
5. 決定論的検証を作れるなら、その入口を既存プロジェクト方式で追加し、検証情報へ反映する。
6. メタハーネスへ統合すべき学びがあれば更新する。

出力要件:
- 追加・更新したファイルを列挙する。
- どの完了条件をどの検証へ対応付けたか示す。
- まだ決定論化できていない点を明示する。

# 導線を整備する目的

* 前提
  * AIエージェントはセッション毎にドメイン知識をゼロから収集する必要がある（セッション毎に知識が揮発する）
  * 過不足なく必要な情報を必要な時に参照する必要がある
    * 常にすべての情報を参照すればいい訳ではない（コンテキストウィンドウ上限やLost in the Middleの問題）
* 目的
  * 必要な知識（ハーネス）を見つけられないままタスクを遂行して失敗するのを避けるため
  * 知識（ハーネス）を見つける過程を効率化するため

# 執筆ルール

* 日本語で書く
* SSoT（Single Source of Truth、１事実１箇所） を厳守する
* ドメイン固有の知識を書く
  * LLMがすでに知っている知識は書かない（一般論など）
* 「完了条件の検証」や「成果物の品質の確認」は決定論的に検証できないかを検討する
  * 前提知識：オーナーの完了条件を決定論的に検証できるならば、AIエージェント＋ハーネスでオーナーの要求を完璧にこなせる
* 用語を揃える
* 同一レイヤーに既存ファイルがある場合、1つ参照して書式・用語を合わせる
* 最新情報のみを保持する（古くなった情報は削除する）

## プログラムの知識を記述する際のルール

* 「手続き」ではなく「振る舞い」を箇条書きで記述する
* コーナーケース・例外時の振る舞いも明記する

## markdownを書く際のルール

* `#` の見出しで段組みを作る
